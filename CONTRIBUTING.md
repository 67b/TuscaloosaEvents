# Contributing to TuscaloosaEvents

Thank you for your interest in contributing to TuscaloosaEvents.

This project is intentionally designed as an open, collaborative, and educational sandbox for learning:

- Git and GitHub workflows
- Branching and pull requests
- CI/CD pipelines
- Automated testing
- GitHub Actions
- AI-assisted software development
- APIs
- Static website hosting
- Event aggregation and calendar standards

The goal is not perfection. The goal is learning, experimentation, and continuous improvement.

Whether you are an experienced developer, student, hobbyist, friend, or family member — contributions are welcome.

---

# Project Philosophy

This repository values:

- Curiosity over perfection
- Collaboration over gatekeeping
- Simplicity over unnecessary complexity
- Learning by doing
- Respectful and constructive feedback
- Experimentation and iteration

Mistakes are expected and part of the learning process.

---

# Ways to Contribute

You can contribute in many ways, including:

- Improving documentation
- Fixing bugs
- Improving accessibility
- Enhancing mobile responsiveness
- Adding event sources
- Improving event parsing reliability
- Improving performance
- Improving UI/UX
- Adding tests or validation
- Improving GitHub workflows
- Suggesting ideas through Issues
- Helping beginners learn GitHub workflows

Even small contributions are valuable.

---

# Development Workflow

## 1. Fork the Repository

Create your own fork of the repository.

## 2. Create a Branch

Create a branch for your work.

Examples:

bash git checkout -b improve-mobile-layout git checkout -b add-new-event-source git checkout -b fix-calendar-bug 

Try to keep branches focused on a single improvement.

---

## 3. Make Changes

Please aim to:

- Keep code readable
- Keep solutions simple
- Avoid unnecessary dependencies
- Preserve compatibility with GitHub Pages hosting
- Maintain the educational nature of the project

If introducing a larger architectural change, consider opening an Issue first for discussion.

---

## 4. Test Your Changes

Before submitting:

- Ensure the site still loads correctly
- Ensure generated JSON remains valid
- Ensure GitHub Actions still succeed
- Verify event data formatting when applicable
- Test mobile layouts when modifying UI

---

## 5. Submit a Pull Request

When opening a Pull Request:

- Clearly describe your change
- Explain why the change is helpful
- Include screenshots for UI changes when possible
- Keep PRs reasonably focused and small

Constructive discussion is encouraged.

---

# AI-Assisted Development

This project openly embraces AI-assisted development tools such as:

- ChatGPT
- GitHub Copilot
- OpenAI Codex
- Claude
- Other AI coding assistants

Using AI tools is allowed and encouraged.

However:

- Review AI-generated code carefully
- Understand code before submitting it
- Avoid blindly committing generated output
- Prioritize maintainability and readability

AI should assist learning — not replace understanding.

---

# Coding Guidelines

## General Principles

Prefer:

- Readability
- Simplicity
- Clear naming
- Small focused functions
- Lightweight solutions

Avoid:

- Overengineering
- Large frameworks unless justified
- Excessive dependencies
- Breaking existing workflows unnecessarily

---

# Event Data Philosophy

Event data quality matters.

Please try to ensure:

- Dates are accurate
- Links are valid
- Duplicate events are minimized
- Data remains structured consistently
- Failures degrade gracefully

Partial data is usually better than broken pipelines.

---

# Git Commit Suggestions

Commit messages do not need to be perfect.

Helpful examples:

- Fix mobile layout spacing 
- Add UA theater event source 
- Improve JSON validation
- Update README screenshots 
- Fix duplicate event filtering 

Clear and simple is preferred.

# Beginner Contributors Welcome

If you are new to:

- Git
- GitHub
- Pull Requests
- JavaScript
- GitHub Actions
- Open source collaboration

# Reporting Issues

If you encounter a problem:

- Open an Issue
- Describe the problem clearly
- Include screenshots if relevant
- Include steps to reproduce the issue

Feature suggestions are also welcome.

---

# Security and Responsible Use

Please do not:

- Commit secrets or API keys
- Scrape sources aggressively
- Abuse third-party services
- Introduce malicious code
- Violate website terms of service intentionally

Respect source websites and community resources.
